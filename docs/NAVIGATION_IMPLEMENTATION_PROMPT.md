# CyChronos 案内機能 実装プロンプト

## 目的

既存のルート確認画面を、初級〜中級サイクリストが走行中に画面を頻繁に触らず使える自転車ナビへ拡張する。片道・往復の既存フローを壊さず、学生チームでも維持できる料金と複雑さに抑える。

## 技術的な前提

- Flutter、Express.js、Google Maps Flutter、geolocatorを継続利用する。
- 経路と日本語の曲がり案内は、既存のMapbox Directions API `cycling` プロファイルから取得する。
- Mapbox Navigation SDKは導入しない。Directions APIはルート取得時と必要な再検索時だけ呼ぶ。
- 音声は端末標準TTS、振動はFlutter標準APIを使い、音声合成の外部API料金を発生させない。
- MapboxトークンはExpress内だけで扱い、Flutterへ渡さない。

## 必須要件

1. 案内開始時に現在地を取り直し、その位置を往復時の帰着地点として保存する。
2. 走行中は現在地、進行方向、走行済み区間、残り距離、残り時間を更新する。
3. 次の曲がり方、道路名を含む案内文、曲がり角までの距離を大きく表示する。
4. 曲がり角の手前で日本語音声と振動を一度ずつ通知し、同じ案内を連続再生しない。
5. 音声のオン・オフを走行画面から切り替えられる。
6. GPS誤差を考慮しながらルート逸脱を判定する。連続3回の逸脱で再検索し、再検索は60秒以上空ける。
7. 片道の目的地、往復の目的地、復路の出発地点への到着を自動判定する。
8. 往復では到着後に滞在を開始し、設定時間後またはボタン操作で復路を表示する。
9. 位置情報や再検索に失敗しても画面を壊さず、利用者に状態と再試行方法を表示する。
10. 案内中は画面の自動消灯を防ぎ、終了・滞在・画面破棄時に必ず解除する。

## 料金・通信量の制約

- 通常走行中にDirections APIを繰り返し呼ばない。
- GPS計算、残距離、曲がり判定は端末内で行う。
- 再検索は逸脱の連続確認とクールダウンを設ける。
- APIキーには利用上限、請求アラート、アプリ/API制限を設定できる構成を維持する。

## 完了条件

- 案内計算の単体テストで、残距離、次の案内、逸脱距離、到着付近を確認できる。
- ウィジェットテストで片道開始・終了、往復の滞在・復路、位置更新、到着を確認できる。
- バックエンドテストでDirections APIに日本語手順のパラメータが渡ることを確認できる。
- `flutter analyze`、`flutter test`、バックエンドテストが成功する。
- Androidのビルドを実行し、ビルド環境以外のコード起因エラーがないことを確認する。
